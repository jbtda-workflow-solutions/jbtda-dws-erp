# Agent Instructions & Execution Constraints

This file is the root agent operating manual for the JBTDA-DWS-ERP repository.
All AI agents working in this codebase MUST read and follow these rules before
writing any code.

## Zero-Memory Protocol

**Never assume context from a previous chat session.** The sole source of truth
is the code and documentation committed to this repository. Begin every session
by reading:

1. `AGENT_SPECIFICATION.md` — master spec and architecture
2. `docs/ARCHITECTURE.md` — topology and service boundaries
3. `docs/DATABASE_SCHEMA.md` — current Prisma schema and migration log
4. `docs/SECURITY.md` — auth mechanics and RBAC rules
5. `docs/CHANGELOG.md` — latest changes

## Mandatory Rules

1. **Documentation first:** Document architectural decisions and data model
   changes in `/docs` before or immediately upon implementation.
2. **Changelog entries:** Every route, migration, dependency, or schema change
   must append an entry to `docs/CHANGELOG.md`.
3. **Multi-tenancy:** Every business-domain query must include
   `where: { organizationId: request.organizationId }`.
4. **Integer money:** Store all monetary values as `BIGINT` cents. Never use
   `FLOAT`, `DOUBLE`, or `REAL`.
5. **No AI in production:** The built application must be 100% deterministic
   TypeScript. No runtime LLM API calls.
6. **Prisma migrations:** Use `prisma migrate dev` locally;
   `prisma migrate deploy` in CI/CD. Never edit migration SQL by hand.
7. **snake_case PostgreSQL:** All column and table names use `snake_case` as
   generated by Prisma's default mapping.
8. **Containerization & Deployment (Unified Monolith):** The application MUST be
   built using a single root `Dockerfile` that utilizes a multi-stage build. The
   build must compile the React frontend, compile the Fastify backend, and package
   them together into a single runtime image. Fastify serves the frontend assets
   via `@fastify/static`. Do not provision separate frontend hosting.
9. **File Tree & Pre-Modification Verification:** Agents MUST review the complete
   file structure below before creating, modifying, or moving files to prevent
   duplicating files across directories. Whenever files are added, removed, or
   moved, the agent MUST update this `Directory Layout` section in `AGENTS.md`
   and append an entry to `docs/CHANGELOG.md` to keep the source of truth accurate.
10. **No Autonomous Git Commits:** Never run `git commit` or `git push` on behalf
    of the user. The user will manage git staging, commits, and pushes manually.

## Tech Stack Quick-Reference

| Layer | Technology |
|-------|-----------|
| Frontend | React 18/19, Vite, TypeScript, Tailwind CSS, Radix UI / shadcn/ui |
| Backend API | Fastify, TypeScript, Prisma ORM |
| Database | PostgreSQL (GCP Cloud SQL) |
| Auth | Google OAuth 2.0 / OIDC via `google-auth-library` |
| Session | Signed + encrypted HttpOnly cookie (SameSite=Strict) |
| Hosting | GCP Cloud Run (Single Unified Container serving API + SPA) |
| Automation | n8n on Cloud Run (async webhooks only) |
