# Agent Instructions & Execution Constraints

This file is the root agent operating manual for the JBTDA-DWS-ERP repository.
All AI agents working in this codebase MUST read and follow these rules before
writing any code.

## Zero-Memory Protocol (Tiered Context Loading)

**Never assume context from a previous chat session.** The sole source of truth
is the code and documentation committed to this repository. To keep token usage
lean while maintaining 100% accuracy, load context in two tiers:

### Tier 1 — Always Read at Session Start
1. `AGENTS.md` — root operating rules & directory layout (auto-loaded)
2. `docs/modules/README.md` — canonical Product Module registry & invariants
3. `docs/CHANGELOG.md` — **top ~60 lines only** (latest 1–2 releases)

### Tier 2 — Load On Demand (Task-Scoped)
- **Working on a specific Product Module:** Read *only* `docs/modules/<module>.md`
- **Core financial rules / GST / integer-cent invariants:** `AGENT_SPECIFICATION.md`
- **API routes, topology, Cloud Run env vars & secrets:** `docs/ARCHITECTURE.md`
- **Auth, session cookies, crypto, or 7-Role RBAC matrix:** `docs/SECURITY.md`
- **Database models & fields:** Read `backend/prisma/schema.prisma` directly (`docs/DATABASE_SCHEMA.md` holds invariants & migration log)
- **UI/UX styling & component geometry:** `docs/DESIGN_SYSTEM.md`
- **Building or updating a delivery stage:** Read the target stage in `docs/STAGES_ROADMAP.md`

## Mandatory Rules

1. **Documentation first:** Document architectural decisions and data model
   changes in `/docs` before or immediately upon implementation.
2. **Changelog entries:** Every route, migration, dependency, or schema change
   must append an entry to `docs/CHANGELOG.md`.
3. **Multi-tenancy:** Every business-domain query must include
   `where: { organizationId: request.organizationId }`.
4. **Integer money:** Store all monetary values as `BIGINT` cents. Never use
   `FLOAT`, `DOUBLE`, or `REAL`.
5. **No AI in production:** The built application must be 100% deterministic
   TypeScript. No runtime LLM API calls.
6. **Prisma migrations:** Use `prisma migrate dev` locally;
   `prisma migrate deploy` in CI/CD. Never edit migration SQL by hand.
7. **snake_case PostgreSQL:** All column and table names use `snake_case` as
   generated by Prisma's default mapping.
8. **Containerization & Deployment (Unified Monolith):** The application MUST be
   built using a single root `Dockerfile` that utilizes a multi-stage build. The
   build must compile the React frontend, compile the Fastify backend, and package
   them together into a single runtime image. Fastify serves the frontend assets
   via `@fastify/static`. Do not provision separate frontend hosting.
9. **File Tree & Pre-Modification Verification:** Agents MUST review the complete
   file structure below before creating, modifying, or moving files to prevent
   duplicating files across directories. Whenever files are added, removed, or
   moved, the agent MUST update this `Directory Layout` section in `AGENTS.md`
   and append an entry to `docs/CHANGELOG.md` to keep the source of truth accurate.
10. **Local Git Commits Allowed / Push Requires Explicit Authorization:** Agents
    MAY stage and create local git commits (`git add` and `git commit`) using
    concise, conventional commit messages at the conclusion of any logical task
    or module revision, and SHOULD report the commit hash and message to the
    user. Agents MUST NOT run `git push` autonomously; every `git push` requires
    explicit user authorization for that push. Once explicitly authorized by the
    user, the agent may execute `git push` to the remote repository.
11. **Local Type Verification Allowed / No Runtime Execution:**
    Agents MAY run `npm install --cache /tmp/.npm-cache`, `npx prisma generate`,
    and non-emitting typecheck commands (`npm run typecheck`, `tsc --noEmit`, or
    `npm run build`) solely to verify TypeScript types and prevent compiler breaks
    before concluding tasks.
    Agents MUST NOT run `npm run dev`, start background dev servers, or execute
    runtime application code on the host machine. The development machine is not
    used to run, demo, or execute the project. Production builds, runtime execution,
    and database migrations remain strictly handled by Cloud Build / Docker during
    deployment to Cloud Run. All new dependencies must still be declared directly in
    `package.json` manifests.
12. **Clean Imports & Compiler Tolerance:** Frontend builds use `tsc && vite build`.
    Never leave unused icon imports or variables in files. `frontend/tsconfig.json`
    has `noUnusedLocals: false` and `noUnusedParameters: false` configured as an
    operational tolerance safeguard against transient Docker build breaks, but
    agents must always keep imports clean and prune unused symbols.
13. **Module-Gate Review Protocol:** Development proceeds one module at a time per
    `docs/STAGES_ROADMAP.md`. When a module is completed, the agent MUST mark its
    checklist items `[x]` in `docs/STAGES_ROADMAP.md`, synchronize `AGENTS.md` and
    `docs/CHANGELOG.md`, commit the changes locally with a conventional git commit
    message (or provide it if uncommitted), and STOP for user review and explicit
    `git push` authorization before beginning the next module.
14. **Zero-Ambiguity Entrypoint & Configuration Documentation Protocol:**
    Every network entrypoint, access path, API route, infrastructure probe,
    webhook callback, and client route MUST be explicitly, exhaustively documented
    in `docs/ARCHITECTURE.md` and `docs/SECURITY.md`. No entrypoints, routes, or
    behaviors may be "implied" or omitted on the assumption that they are "industry
    standard" (e.g. `/healthz`, OAuth callbacks, SPA catch-alls, static assets,
    configuration endpoints).
    Furthermore, every environment variable, runtime configuration parameter, and
    Secret Manager secret read by the application MUST be documented in
    `docs/ARCHITECTURE.md` (single source of truth) with:
    - Exact variable name and source (Cloud Run env var or Secret Manager)
    - Concrete purpose
    - Explicit permitted values or types (e.g. `"true"` | `"false"`, non-empty string)
    - Concrete failure behavior if missing, invalid, or left empty
    No environment variable or secret may be left undocumented, optional without
    an explicit default, or allowed to be an empty string without explicit validation
    and failure handling.
15. **Chat-First Visibility & Agent Studio Reporting:**
    Because the user operates primarily in Antigravity Agent Studio rather than
    a local IDE file tree:
    - **Chat-First Change Summaries:** Always summarize what changed (new/modified
      routes, schema fields, UI behavior, and typecheck/build verification results)
      directly in the chat response—never assume the user will open raw files to
      inspect edits.
    - **Pre-Push Review Bundle:** Whenever requesting `git push` authorization,
      include the unpushed commit list (`git log origin/main..HEAD --oneline`) and
      the affected file paths so the user can review before authorizing.
    - **Artifacts for Large Specs & Plans:** Use Markdown Artifacts for extensive
      module plans, schema proposals, or architecture reviews so tables and
      diagrams render cleanly in Agent Studio.

## Tech Stack Quick-Reference

| Layer | Technology |
|-------|-----------|
| Frontend | React 18/19, Vite, TypeScript, Tailwind CSS, Radix UI / shadcn/ui |
| Backend API | Fastify, TypeScript, Prisma ORM |
| Database | PostgreSQL (GCP Cloud SQL) |
| Auth | Google OAuth 2.0 / OIDC via `google-auth-library` |
| Session | Signed + encrypted HttpOnly cookie (SameSite=Strict) |
| Hosting | GCP Cloud Run (Single Unified Container serving API + SPA) |
| Automation | n8n on Cloud Run (async webhooks only) |

## Cloud Run Runtime Configuration (Variables & Secrets)

The application relies strictly on Google Cloud Run container configuration (zero `.env` files in production).
**Single Source of Truth:** See `docs/ARCHITECTURE.md` (*Configuration via Cloud Run Container Interface*) for the complete, authoritative specification of Cloud SQL Unix socket mounting (`/cloudsql/<INSTANCE_CONNECTION_NAME>`), all Environment Variables, and all Secret Manager secrets with permitted values and failure behaviors.
